# 3주차 Observation

## 과제 1

루트 서버는 www.korea.ac.kr의 A 레코드를 관리하지 않으므로 .kr 담당 서버를 NS 레코드로 위임했다. RD를 끄고 루트부터 직접 다음 서버를 찾아갔다.
glue가 없으면 NS 이름을 루트부터 별도로 해결한 뒤 원래 질의를 이어가며, 이때의 모든 질문도 path에 포함한다. 실제 고려대 캡처에서는 glue가 있어 추가 조회가 없었고, 모의 무glue 테스트에서는 NS 주소 조회 1회가 추가됐다.
캡처 당시 198.41.0.4 → 210.101.61.1 → 163.152.11.6의 세 서버에 질문해 163.152.6.10을 얻었다. 일반 클라이언트는 보통 재귀 리졸버에 한 번 질문하고 이 탐색을 맡긴다.

## 과제 2

직접 캡처한 위임 응답 #2는 Answer=0과 Authority의 NS를 담고, 최종 응답 #6는 Answer의 A=163.152.6.10를 담았다. 최대 DNS 응답은 341 bytes였다.
마지막 두 레이블 비교는 wikipedia.org → wikimedia.org를 제3자로 오판했다. 실제로는 Wikimedia 자체 CDN이다.
home-wifi, other-wifi에서 비교 가능한 CDN 9개 중 7개가 다른 주소 집합을 보였지만, 측정 날짜도 달라 네트워크 효과를 분리하거나 최단 거리 유도를 입증할 수 없다.
